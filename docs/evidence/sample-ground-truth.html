Why the tools disagree, and which one to follow

Three different numbers have now appeared for files this project can measure exactly, and the pattern behind them is the most useful thing on this page.

File What is really there mediainfo says ffprobe says
sample.mp3 (VBR) 6090 frames, the first a Xing frame declaring 6089 6089 6089
cbr-64-mono-info.mp3 (CBR) 79 frames, the first an Info frame declaring 78 79 78
truncated.mp3 96 complete frames; the file was cut to 20,000 bytes 6089 96

mediainfo is not consistent with itself. On the variable-bitrate files it reports the number the metadata frame declares, which is why a file cut to 20,000 bytes still reports 6089 — a figure describing a file that no longer exists. On the constant-bitrate file it counts frames itself, and so includes the Info frame that carries no audio. ffprobe counts in both cases, though on the truncated file it counts a frame missing 234 of its 261 bytes.

This service counts frames whose bytes are all present, and excludes a leading metadata frame: 6089, 78 and 95 for the three files above. Four independent signals support that reading of the sample — mediainfo, ffprobe, the Xing field itself, and the channel-mode split, in which the single stereo frame is the metadata frame and all 6089 audio frames declare joint stereo. The reasoning is recorded in decisions.md D1, D11 and D17.
