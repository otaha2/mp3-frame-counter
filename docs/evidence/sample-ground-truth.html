The reference tools do not agree with each other

On cbr-64-mono-info.mp3 mediainfo reports 79 and ffprobe reports 78. The file holds 79 structurally valid frames, the first of which is an Info metadata frame whose own frame-count field reads 78.

File Metadata frame mediainfo behaviour
sample.mp3 (VBR) Xing, field = 6089 Reports 6089 — the field's value, excluding the metadata frame
cbr-64-mono-info.mp3 (CBR) Info, field = 78 Reports 79 — a physical count, including the metadata frame

mediainfo is therefore not self-consistent across the two files: it appears to read the declared field for a variable-bitrate stream and to count frames itself for a constant one. ffprobe excludes the metadata frame in both cases, as does each file's own header field. This service follows the consistent reading — see decisions.md D11.

The discrepancy, resolved

Physical walk: 6090. mediainfo, ffprobe, and the file's own Xing field: 6089. The difference is exactly frame 1 — the Xing metadata frame, which is a validly-shaped frame carrying no audio. Reference tools exclude it; the Xing field's byte count (which includes its own frame) confirms the count field describes the frames after it. The channel-mode split is a fourth, independent witness to the same boundary: the metadata frame declares stereo while all 6089 audio frames declare joint stereo. Decision: report 6089-style counts — physical frames minus a detected Xing/Info/VBRI frame (decisions.md D1). Expected count for this file: 6089.
